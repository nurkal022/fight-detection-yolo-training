# Разделение app и app2

## Независимость приложений

`app` (Flask веб-приложение) и `app2` (standalone pygame приложение) полностью независимы:

### 1. Пути к моделям
- **app**: Использует абсолютный путь к модели из `app/config.py`
- **app2**: Использует абсолютный путь к модели из `app2/config.py`
- Оба могут использовать одну и ту же модель файл без конфликтов

### 2. Базы данных
- **app**: Использует SQLite базу `detection_system.db` в корне проекта
- **app2**: Не использует базу данных (standalone приложение)

### 3. Камеры
- **app**: Управляет камерами через Flask API и базу данных
- **app2**: Прямое подключение к камере через OpenCV
- ⚠️ **Важно**: Если оба приложения используют одну и ту же камеру одновременно, могут быть конфликты доступа

### 4. Telegram уведомления
- **app**: Отправляет уведомления через Flask backend
- **app2**: Отправляет уведомления напрямую
- ⚠️ **Примечание**: Если оба работают одновременно, могут отправляться дубликаты уведомлений

### 5. Порты и ресурсы
- **app**: Запускается на Flask порту (обычно 5000)
- **app2**: Не использует сетевые порты (standalone)
- Нет конфликтов портов

## Рекомендации

1. **Для демонстрации**: Можно запускать оба одновременно, но лучше использовать разные камеры
2. **Для продакшена**: Выберите одно приложение в зависимости от потребностей:
   - **app**: Для веб-интерфейса и управления через браузер
   - **app2**: Для автономной работы без веб-сервера

## Исправленные проблемы

1. ✅ Application context в `generate_stream` - детектор передается как параметр
2. ✅ Абсолютные пути к моделям - нет конфликтов при запуске из разных директорий
3. ✅ Независимые конфигурации - каждый app имеет свой config.py
